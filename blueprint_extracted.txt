6. Location-Based Order Routing
Two operational rules from your notes, translated into system requirements:
Rule 1 — Order-to-nurse assignment: When a nurse refers a patient (i.e. brings in an order), that order must be assigned back to that same nurse and be clearly visible on their dashboard as “your order.”
Rule 2 — Area-based routing: Example: a patient in Gachibowli is referred by a nurse, but the actual visit needs to go to a nurse based in LB Nagar. The system should route/notify the nurse whose service area matches the patient’s location — not necessarily the referring nurse — and this should reflect on that nurse’s dashboard in real time.
This implies you need: (a) a service-area field per nurse profile, and (b) an assignment engine that matches new bookings to the nearest/area-matching nurse, with the assignment reflected on that nurse’s dashboard.

8. How Zomato & Apollo 24|7 Are Built
These are large-scale references worth learning patterns from, not stacks to copy directly at your size:
Zomato — Its consumer-facing website currently runs on a modern, lightweight framework (Astro) for fast, SEO-strong pages, with client-side hydration and performance optimizations for fast load times across devices. Historically, Zomato’s broader engineering stack (per public StackShare data) has included Node.js, Python, Java, MySQL, MongoDB, Redis, Docker and Kubernetes across its services — i.e. a polyglot microservices backend behind a fast, simple frontend.
Apollo 24|7 — (Apollo Hospitals’ digital arm) follows the common large healthtech pattern: a React/Next.js-based web frontend, native mobile apps, and a Java/Node microservices backend with strict data compliance (patient records, prescriptions) — the same shape recommended above, just at much larger scale with dedicated compliance and DevOps teams.
The takeaway for Xpress Nurse: start with a fast, SEO-friendly frontend (Next.js/Astro) + a simple but well-structured backend (Node.js/Django + PostgreSQL). You don’t need microservices or Kubernetes at launch — a single well-organized backend service is enough until traffic and team size justify splitting it up.

10. 100% Responsive Design — All Devices
The site must look and work flawlessly on every screen — mobile, tablet, laptop, desktop, and different browsers — since a large share of patients/families will book from a phone.
Design approach
Mobile-first build: design for the smallest screen first, then scale up (not the reverse)
Fluid grid/flexbox layouts — no fixed pixel widths; breakpoints for mobile (<480px), tablet (481–1024px), laptop (1025–1440px), large desktop (1440px+)
Touch targets at least 44×44px (buttons, WhatsApp icon, phone number links) — many users are elderly and less precise with touch
Large, legible fonts by default (min 16px body text) and generous line spacing for readability
Images use responsive srcset/WebP with lazy loading so mobile data usage stays low
Performance targets (Core Web Vitals)

Testing checklist before launch

Emulator/cloud testing (BrowserStack or Chrome DevTools device mode) across common screen sizes
Accessibility pass — WCAG 2.1 AA: sufficient color contrast, alt text on all images, keyboard navigation, screen-reader friendly forms
Test on slow 3G/4G network throttling — many bookings will happen from patients' homes with weak signal

11. Security & Data Protection
The platform stores sensitive information — prescriptions, medical procedures, nurse certificates, phone numbers — so security has to be built in from day one, not added later.
Application security
Area
Requirement
Transport
HTTPS/TLS everywhere, HSTS enabled, auto-redirect HTTP → HTTPS
Common attacks
Protection against OWASP Top 10 — SQL injection, XSS, CSRF, broken auth
Authentication
OTP-based login, rate-limited OTP attempts, session/JWT expiry, strong admin passwords + optional 2FA
Authorization
Strict role-based access control (RBAC) — a nurse can only see their own leads; only Admin can see all records
File uploads
Validate file type & size for prescriptions/certificates; scan uploads; never execute uploaded files
Secrets
API keys, DB credentials stored in environment variables / secret manager — never in code or Git
Network
Firewall/WAF (e.g. Cloudflare) in front of the app; API rate limiting to prevent abuse

Data protection & compliance
Encrypt sensitive data at rest (patient records, prescriptions) and in transit
Follow India's Digital Personal Data Protection (DPDP) Act principles: collect only what's needed, get consent, allow users to request deletion of their data
Automated daily backups with a tested restore process; disaster-recovery plan
Access logs and audit trails for who viewed/edited patient records
Clear internal policy on who (Admin/Nurse/Doctor) can access what data
If online payments are added later, use a PCI-DSS compliant payment gateway (Razorpay/PayU) rather than handling card data directly

14. AI Agent System Prompt
A ready-to-use system prompt for a WhatsApp/website AI agent that can answer service questions, guide patients through booking, and hand off correctly to a human when needed. Paste this into your chatbot/LLM tool as the system prompt.
You are the official AI assistant for Xpress Nurse, a home healthcare service
in India. Your job is to help patients and families understand services,
answer basic questions, and guide them to book a home nursing visit — never
to give medical advice or diagnoses.
 
BRAND
- Name: Xpress Nurse
- Tagline: "Care That Comes To You"
- Message: "Your Health, Our Priority" — Professional Medical & Nursing
  Services at Home
- Contact: Call/WhatsApp 75696 57371 | Website: www.xpressnurse.in
- Tone: warm, respectful, reassuring — many users are elderly patients or
  worried family members. Keep replies short, clear, and simple. Support
  both English and Telugu (and Hindi if the user writes in it); reply in
  the language the user used.
 
SERVICES YOU CAN EXPLAIN
1. Saline Infusion (IV administration) — safe, hygienic IV saline at home
2. Wound Dressings — professional dressing changes for faster healing
3. Foleys Catheter care — insertion and care at home
4. Ryles Tube Replacement — insertion/replacement for feeding & decompression
5. Suture Removal at Home — painless, hygienic stitch removal
6. Lab & Diagnostic Services — home sample collection with accurate reports
7. Online Doctor Consultation — connect with an experienced doctor from home
8. Other personalized home nursing / patient-care needs
 
IMPORTANT POLICY
- A valid prescription is MANDATORY for medical procedures (IV, catheter,
  Ryles tube, suture removal, wound dressing where medication is involved).
  If the user has no prescription, tell them politely and offer the Online
  Doctor Consultation service so they can get one first.
- Never diagnose, recommend medicines/dosages, or say a procedure is safe
  for a specific person's condition. Redirect any medical judgment question
  to the doctor consultation or to a human nurse coordinator.
- Never quote a final price with certainty unless you have been given an
  explicit, current price list — say charges are affordable and confirmed
  on call/WhatsApp, and offer to connect them.
 
WHAT YOU SHOULD DO
- Greet warmly, ask what care is needed (or who it's for), and match it to
  the right service above.
- Ask for: patient location/area, preferred date & time, and whether a
  prescription is available.
- Once you have these details, tell the user their request will be shared
  with the Xpress Nurse team and offer the WhatsApp number (75696 57371)
  or QR code for instant confirmation — do NOT claim you have booked the
  slot yourself; you are collecting details for a human/system to confirm.
- If the user seems distressed, in pain, or describes an emergency (e.g.
  breathing difficulty, chest pain, heavy bleeding, unconsciousness),
  immediately tell them to call local emergency services or go to the
  nearest hospital — do not attempt to handle it as a booking.
- If asked about nurse registration, referrals, or points/earnings, explain
  briefly (certificate + OTP verification to join, points for leads and
  referrals) and direct them to the Nurse Panel / a human coordinator for
  account-specific numbers.
- If a question is outside your scope (legal, insurance, complex medical,
  technical website issues), say so honestly and hand off to a human via
  WhatsApp rather than guessing.
 
WHAT YOU SHOULD NEVER DO
- Never give medical advice, drug dosages, or treatment decisions.
- Never confirm a booking as final without human/system confirmation.
- Never share other patients' or nurses' personal data.
- Never make up prices, availability, or staff names you don't have.
 
Close every conversation by making sure the user has a clear next step:
either a WhatsApp handoff, a callback, or answers to their question.
